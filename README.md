# SafeCross AI

SafeCross AI ranks street intersections by relative crash risk for the
following period, using recent crash history, weather, and OpenStreetMap
road-design attributes.

## Quick start (no training required)

You do **not** need to run any notebook, download raw data, or have a GPU
to see the app work:

```bash
pip install -r requirements.txt
python scripts/export_streamlit_assets.py   # only needed once, or after retraining
streamlit run app/streamlit_app.py
```

Run this from the **repository root**, not from inside `app/`.

The app only reads files already saved to disk — it never trains or
retrains a model. XGBoost inference is forced to CPU at load time
(`force_cpu_for_deployment()` in `app/app_utils.py`), even if the model was
originally trained on a GPU in Colab.

## Full pipeline (only needed to retrain or update the model)

1. **Notebook 1**  collects the raw crash, OSM, and
   weather data into `data/raw/` and `data/processed/`.
2. **Notebook 2** (`SafeCross_AI_Notebook2.ipynb`) builds the modeling
   panel, engineers features (with a missingness audit for the OSM
   road-design tags), trains and compares five models, locks the best one
   on the untouched test period, and — critically for deployment — saves:
   - `models/safecross_model_bundle.joblib` — fitted preprocessor + fitted
     model + everything the app needs to run inference, kept as one bundle
   - `models/safecross_model_metadata.json` — selected model, threshold,
     prediction horizon, target, feature lists, training device
   - `data/processed/safecross_intersection_week_panel.parquet` — the
     source the export script builds the demo CSV from
   - `data/processed/safecross_test_predictions.parquet`
   - `reports/metrics/validation_model_comparison.csv`
   - `reports/metrics/selected_model_test_metrics.json`

   Notebook 2 ends with a **deployment readiness check** cell that verifies
   every one of these files exists and is correctly structured before
   moving on — if that cell passes, the notebook is done.
3. **Notebook 3** (`SafeCross_AI_Notebook3.ipynb`) loads those saved files
   — it does not retrain anything — and produces calibration curves,
   permutation importance, error analysis, subgroup/time-stability checks,
   an interactive map, a model card, and the per-intersection recommendation
   table, all under `reports/notebook_02_03/`.
4. **`scripts/export_streamlit_assets.py`** reads Notebook 2's saved panel
   and writes a small, public-safe demo CSV to `data/sample/`, along with a
   deployment version summary and a lean `requirements.txt` for the app
   itself.

Run Notebook 2 in Google Colab with a GPU runtime — XGBoost will use it
automatically if available, and falls back to CPU otherwise. Notebook 3 and
the export script have no GPU requirement and can run anywhere, including
locally.

**Note:** the export script regenerates `requirements.txt` at the repo root
with a lean, deployment-only package list. If you also want to run the
notebooks in the same environment, keep a separate `requirements-notebooks.txt`
(pandas/numpy/matplotlib/osmnx/networkx/pyarrow/scikit-learn/joblib/folium/
xgboost/lightgbm) or reinstall those packages after running the export
script.

## Deploying to Streamlit Community Cloud

1. Push the repository to GitHub, including `models/safecross_model_bundle.joblib`
   and `models/safecross_model_metadata.json`. Check the bundle's file size
   first (`ls -lh models/`) — use Git LFS if it exceeds GitHub's normal limit.
2. On Streamlit Community Cloud: **Create app** → select this repository and
   the `main` branch.
3. Set the entrypoint to `app/streamlit_app.py`.
4. Match the advanced-settings Python version to whatever you used to test
   locally.
5. Deploy. Every subsequent push to `main` will redeploy the app.

Before submitting/demoing, test locally in the exact same way judges would
run it: `pip install -r requirements.txt` then `streamlit run app/streamlit_app.py`
from a clean checkout, and confirm no traceback appears anywhere in the flow.

## Notes for reviewers / judges

- The methodological guardrails at the top of Notebook 2 explain what this
  model can and cannot support (see also `app/streamlit_app.py`'s
  Limitations tab, and the model card saved by Notebook 3).
- Model output is presented as a **relative risk tier**, not a raw
  probability — calibration is currently weak enough that a literal
  percentage would overstate precision. Probabilities are still used
  internally throughout evaluation and inference.
- No traceback or error output is committed in the final notebooks — if you
  see one after running a cell, something in your environment differs from
  what's documented here (most likely a missing file from an earlier
  notebook).
